# cache設計書

## 基本設計

- messageはDB
- memberの全件保持はしない
- 呼び出しrole+未認証リストのみ
- それ以外は全てin-memory cache
- 永続化していないものは全て再起動時に再構築

## message cache

- back pressure付きでテーブルごとに直列化(DB構成は`02_DB設計書`参照)
- 起動してない時のメッセージの編集・削除は責務を負わない
- 再起動時にDBに保存されていない最も最近のメッセージまで読み込み保存する
- batch size/timeoutで書き込む

## member cache

- サーバーの重い処理を呼び出した人を保存する
- 最後に重い処理を呼んだ時刻とのmap
- 一定周期で一定時間経った人をclean upする
- 再起動で中身の復元の必要はない

## role cache

> **注意**
> 現在未使用

- サーバー全体のロールのin-memory cache
- 再起動時に完全に再構築

## has-role cache

- 特定のroleごとに異なるキャッシュへ保存する
- 再起動時にREST APIから再取得

## 未承認リスト

- 二つのmapを一定時間ごとにローテーションしながら中身をkickする(個人当たりの厳密な時間は不要)
- 参加で追加、承認で削除
- 再起動時に特定のロールがない人を走査し再構築

## channel cache

- 親channelを全件保持
- 再起動時にREST APIから再構築

## フォーラムの投稿

- lruでスレ主id及び呼び出しlimitも含めて保持
- 過去の投稿になっていないものをREST APIから再構築、投稿者はDB問い合わせ
